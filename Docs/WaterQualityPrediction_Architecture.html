No live sensors — this pipeline is built entirely around existing water-quality datasets (CPCB/WHO records, Kaggle, UCI, USGS). Everything downstream of Stage 1 works in batches, not real-time streams: scheduled loads, versioned snapshots, and dataset-level drift checks replace MQTT feeds and per-sensor health monitoring.

What's Novel vs. Literature

  • SHAP + LIME + counterfactuals per prediction — papers 16, 19, 20 flag this gap
  • Prediction intervals + confidence-aware alerting — no reviewed paper quantifies uncertainty
  • Dataset-level drift & quality monitoring — unresolved in all 20 papers
  • 6-tier severity + per-parameter tags — beyond the 2–4 class setups in papers 14, 18
  • Corrective-action mapping engine — closes the decision loop, not just a prediction
  • Trend forecast with forecast-level XAI — extends papers 3, 5, 10, 11
  • Multi-dataset fusion with cost-accuracy tradeoff analysis — paper 14 noted this affordability gap

Data Flow Summary

  • Public datasets (CPCB, Kaggle, UCI, USGS) → batch loader → schema & type validation
  • Validated batches → ETL processor → feature store + tabular DB + versioned data lake
  • Raw & validated batches also feed data quality & drift monitoring (Great Expectations, KS-test, PSI)
  • Feature store → feature engineering (interactions, lags, season) → ML prediction engine
  • ML outputs (WQI, WQC class, forecast) → XAI layer → decision support engine
  • Decision support → analyst dashboard (monitoring, XAI, alerts/actions, data quality)
  • Feedback loop: analyst corrections & new dataset batches trigger retraining via the model registry

Technology Stack

  • Sources: CPCB / WHO records, Kaggle, UCI, USGS Water Quality Portal, CTGAN synthesis
  • Ingestion: Scheduled batch loader, Great Expectations, pandas
  • Pipeline: Pandas / PySpark ETL, Feast (feature store)
  • Storage: PostgreSQL, S3 / MinIO, DVC for dataset versioning
  • ML: Random Forest, XGBoost, LSTM/GRU, CTGAN, Quantile RF / conformal prediction
  • XAI: SHAP, LIME, custom counterfactual generator, tree decision-path visualizer
  • Backend: FastAPI / Flask, scikit-learn, PyTorch / TensorFlow, MLflow
  • Frontend: React / Dash, interactive SHAP plots, batch dashboards, alert UI
